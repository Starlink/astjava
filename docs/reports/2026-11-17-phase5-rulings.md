# Phase 5: rulings

These are the decisions made while executing the phase 5 plan ([`2026-11-17-pure-java-ast-phase5-mappings.md`](../superpowers/plans/2026-11-17-pure-java-ast-phase5-mappings.md)) where the plan was wrong, unclear or silent, or where the port departs from Rust or C or keeps a C quirk.
They are copied from the execution ledger (the controller's rulings and the user's decisions) and from each task's report (the implementer's rulings), grouped by task; within a task the implementer's come first, in the order of the report, then the controller's, in the order they were made.
The plan's Task 6 (astEqual) was inserted during the phase, so the tasks are numbered as in the plan as it now stands: Tasks 1 to 5 are as first written, and what was Task 6 is Task 7.
Each ruling gives what was decided, why, and what it costs if wrong.
A later ruling can reverse an earlier one; a ruling that a later one replaced carries a bracketed note saying so.
There are 181 rulings, 163 by the implementers, 18 by the controller and the user.
The phase report is [`2026-11-17-phase5-report.md`](2026-11-17-phase5-report.md).

## Task 1: LutMap

### Implementer

- Ruling: LutMap keeps C's last input and output per direction and returns the kept output for the same input even after LutInterp changes (copied by `copy()`, as C's memcpy) — transform-changing C quirks are copied (phase 2), and the rule "C wins" makes Rust's `lutmap_interp_change_applies_to_a_repeated_value` expect C's values from the probe — cost if wrong: a value transformed again after LutInterp changes gives the old method's result, as jniast/C does; recorded in rust-c-differences.md.
- Ruling: MapMerge's cancellation compares the nominated LutMap with its own Invert attribute, as C does, so an inverted series CmpMap of a LutMap and a copy of itself simplifies to a UnitMap (changing the transformation) and one of a LutMap and its inverse is kept (probed) — Rust folds the list value in — cost if wrong: such a Mapping changes on simplify, as in C; recorded as a C quirk.
- Ruling: a table GetLinear calls linear but whose ends are equal (constant, or within LutEpsilon) is neither replaced nor cancelled, as C's `if/else if` does (probed) — Rust tries the cancellation — cost if wrong: none for C parity; recorded.
- Ruling: the neighbour's Invert is put back with `setInvert(oldValue)` as C's `astSetInvert(neb, old_inv)`, not `swapInvert/restoreInvert`, so an unset Invert becomes set to the same value — cost if wrong: `test("Invert")` on a neighbouring LutMap after a simplification reads true, as in C.
- Ruling: Rust's `monotonic()` tests are translated as TranInverse checks (and the inverse results), since C exposes only TranInverse — cost if wrong: increasing vs decreasing is not asserted directly (the inverse tests cover both).
- Ruling: `GetMonotonic`'s inverse table holds exactly the good values; C sizes it from the bad values counted before its early break, which happens only for a non-monotonic table, whose inverse is undefined — cost if wrong: only a hand-edited dump declaring `Inv = 1` for a non-monotonic table differs (C would read uninitialised entries).
- Ruling: a negative `Nlut` in a dump loads an empty table (`Math.max(0, ...)`, as the other loaders here treat negative counts) where C's allocation would fail — cost if wrong: a corrupt dump reads instead of failing with AST__NOMEM.
- Ruling: `GetLinear` keeps C's arithmetic on bad entries (AST__BAD = -DBL_MAX enters the range and line), which is how C decides the non-finite-entry tables of `lutmap_non_finite_entries_not_linear` — cost if wrong: none; matches C's classes.
- Ruling: the -TAB read stops where C's `GetNamedTable` reports AST__NOTAB; jniast has no table source, so the only tables are a dumped FitsChan's `Tables` KeyMap, and an entry there throws `needs FitsTable` (C would use it as a FitsTable) — cost if wrong: none reachable without FitsTable.
- Ruling: the FITS-WCS read functions take the FitsChan instead of its TabOK value, as C's `TabMapping` receives `this` (common.md) — cost if wrong: none; one test helper passes `new FitsChan()`.
- Ruling: `IsMapTab1D`'s LutMap branch sets `interp` and throws `needs FitsTable` without building `premap`/`postmap` or copying the table, which C uses only to fill the FitsTable it creates next — cost if wrong: none observable (C's temporary `astSetInvert` on the list's Mappings also restores them).
- Ruling: `brad` in `simplify-cases.txt` changes from `needs LutMap` to `needs simplification` — traced with lldb in the pinned C: `cmpmap.c` `Equal` (non-expanded branch) saves and restores the Invert of two components that are the same object in the wrong order, leaving the shared WcsMap of `brad.map` with Invert 0, which `brad.simp` records; Java's recursion guard compares identity and text (phase 2 ruling, `astEqual` not ported), so its WcsMap keeps `Invert = 1`; the dumps differ in that one line and the transforms agree (`brad.map`/`brad.simp` left `simplify.txt`) — cost if wrong: one regression row stays deferred until CmpMap `Equal` is ported; recorded in rust-c-differences.md as a C quirk.
- Ruling: `unit_change_leaves_mappings_alone` is translated by setting `System(1)` of sparse.ast's current Frame to the value it has (any setting through a FrameSet marks integrity lost) in place of Rust's no-op `with_integrity` closure — cost if wrong: none; the dump is unchanged, as the test requires.

## Task 2: MathMap expressions and transformation

### Implementer

- Ruling: a MathMap's saved second Gaussian value is kept in its own random context (Rust's choice), not in C's static variables shared by every MathMap — Review Focus 2 requires a copy to give its original's sequence and threads on copies to agree, which C's shared state prevents (probe cases `random_copies`, `gauss_two_mathmaps` show C's behaviour; tests assert C's single-MathMap values) — cost if wrong: interleaved `gauss` calls on two MathMaps, or on a MathMap and its copy, give different values from C's; recorded as a C quirk.
- Ruling: C's `errno`-trapped maths errors (exp, cosh, sinh, tan, pow, ldexp) give AST__BAD when a finite argument gives a non-finite result, as a glibc build of C does (phase 3 precedent for FitsLogMap); the pinned macOS build gives inf/NaN, so the test lists those 22 probe values explicitly (`ERRNO_TRAPPED`, `ERRNO_CASES`) — cost if wrong: overflowing MathMap expressions give BAD where macOS C gives an infinity (or 0 after `!`).
- Ruling: `nout < 1` is reported with status AST__BADNI (C quirk mirrored; Rust uses BADNO) — cost if wrong: a caller testing for AST__BADNO does not see it, as in C.
- Ruling: `<e>` loads `Math.E`, the correctly rounded `exp(1.0)` C's library gives, because Java's `Math.exp(1.0)` is one ulp high — cost if wrong: none for C parity.
- Ruling: library function values (sin, cos, log, ...) are compared with C to 2 ulp (evaluate case) or 4 ulp (transformations, gauss sequences); every bad, zero, integer and non-libm value is compared exactly — cost if wrong: a last-bit libm difference is accepted, as CLAUDE.md allows.
- Ruling: inputs that are not finite are bad (library rule, as LutMap), but a NaN or infinity made inside an expression (e.g. from the literal `1e999`) is passed through as C does; Rust replaces NaN outputs with BAD — cost if wrong: `y = 1e999-1e999` gives NaN, as C.
- Ruling: `DefaultSeed` uses `System.nanoTime()` in place of C's `clock()` and `System.identityHashCode(context)` in place of the context's address; the shared quick generator is a `static final AtomicLong` (C's mutex-protected static) — cost if wrong: only the unpredictable default seeds differ, which no test can pin.
- Ruling: a loaded dump with `Nfwd` below the number of outputs or `Ninv` below inputs is refused with AST__INNTF and `astInitMathMap`'s message naming `astLoadMathMap` (C reads out of bounds) — cost if wrong: a corrupt dump fails instead of being undefined behaviour.
- Ruling: Poisson's constants that C caches in static variables per mean are recomputed per call (same values; no shared mutable state) — cost if wrong: none.
- Ruling: the compiled function arrays are shared by a copy (never mutated), while C copies them; the random context is copied — cost if wrong: none observable.
- Ruling: `SimplifyRegressionTest.withoutRecords` also drops `AlSimp`, because C's `cmpmap.c` `Simplify` clears AllowSimplify on components it shares with the input (probe case `simplify_input_after`, built from `cap_restricted_component_flags.map`; `MathMapTest.simplifyClearsAllowSimplifyOnSharedComponents` checks Java does the same); without it `cap_restricted_component_flags` failed "simplify() changed the input's dump" though it matches C; it now passes — cost if wrong: a Java bug that clears AlSimp on an input where C does not would go unnoticed by this harness.
- Ruling: `math_inverse_cancel`, `cmpmap_parallel_in_series_merge` and `cap_mathmap_01` change from `needs MathMap` to `needs simplification`; each needs MathMap's `MapMerge` (a MathMap and its inverse with SimpFI/SimpIF cancelling to a UnitMap), which the brief leaves to Task 3 — cost if wrong: three regression rows stay deferred until Task 3.
- Ruling: in `rust-tests.txt` the untranslated MathMap entries get precise reasons: `test_cmpmap.rs` two tests `needs simplification`, `src/units/tests.rs` four tests `UnitsMapper MathMap conversion (out of scope)`, three FITS tests `FITS -LOG axis (out of scope)`; `tests/test_mathmap.rs::test_simplification_simpfi | needs simplification` is added (Rust's `try_merge`, Task 3's MapMerge) — cost if wrong: reasons only; Tasks 3 and 4 translate them.
- Ruling: Rust tests in other files that now run were translated here (as Task 1 did for LutMap): `nonlinear_mathmap_1d`, `numeric_rate_tan_at_zero`, `round_trip_mathmap`, `a_mathmap_needs_a_function_per_output`, six `test_clear_on_set.rs` cases, `polco_loads`, `polco2_loads`, `convert_stops_at_the_first_domain_that_gives_a_conversion`, `a_sip_description_is_rejected_when_it_is_not_linear_over_the_image`; MathMap's rate is mapping.c's numerical rate (C's mathmap.c has no `Rate`) — cost if wrong: none.
- Ruling: the probe draws an even number of Gaussian values from a fresh MathMap before its `mixed` case, so that C's shared saved value does not leak into it — cost if wrong: none; the leak is recorded separately.
- Ruling: C's `Rand` with a Seed below 1 (64-bit `long` + `LONG_MAX`) gives values far outside 0..1; mirrored, recorded as a C quirk — cost if wrong: such seeds give C's odd values.
- Ruling: Rust's `<dig>` of 15 is a Rust bug; Java gives C's `AST__DBL_DIG` of 17 — cost if wrong: none for C parity.

### Controller

- Ruling: keep glibc semantics for overflow and domain trapping — it is what mathmap.c's CATCH_MATHS_OVERFLOW and CATCH_MATHS_ERROR code asks for, and macOS's libm, which only sets MATH_ERREXCEPT, is the outlier — cost if wrong: 30 expected values revert to inf or NaN.
